# 内容操作与部署说明

## 发布不同栏目内容

1. 使用操作员账号登录，进入“内容管理”。
2. 左侧选择新闻中心子栏目、通知公告、领域动态或资源产品栏目。
3. 点击“添加内容”，所属栏目自动带入。
4. 在“基本信息”填写标题、栏目、显示日期和可选来源，然后编辑正文。副标题、关键词、列表简介和置顶位于“更多设置”；首页图片与推荐开关在右侧“首页图片”卡片。
5. 保存草稿，或“保存并预览”；预览仅操作员可见。
6. 点击“立即发布”，内容出现在相应栏目列表。
7. 勾选“推荐到首页对应区域”并发布后，进入该栏目已有的首页区域。

修改已发布内容先形成草稿，点击“发布更新”才替换公开版本。撤回后列表、首页、详情和专属附件停止公开。删除进入回收站，恢复后为草稿，需要重新发布。

显示日期仅控制展示与排序，不会自动定时发布。操作记录保存真实动作时间。

## 图片与列表简介

- **正文图片**：在正文工具栏选择“插入正文图片”，上传 PNG/JPG 后插入当前光标位置。上传过程中暂时不能保存或发布。
- **内容封面**：可选，裁剪为 3:2，用于栏目列表和文章开头，普通文章也会显示封面。
- **首页图片**：在文章编辑右侧“首页图片”上传 PNG/JPG（最大 10 MB，建议横向图片），勾选“推荐到首页对应区域”并发布。首页新闻大图优先展示当前新闻分类中带图片的推荐文章；数据产品卡片也优先使用首页图片，点击进入对应文章。未设置首页图片时沿用内容封面；首页图片不会自动插入正文。更新后需要再次发布才会替换公开图片。
- **图片附件**：上传到附件区后会显示缩略图，在前台文章末尾展示原比例图片并提供原图链接；点击“插入正文”可把它放到正文光标处，同一图片不会在正文、封面和末尾重复展示。
- **文档附件**：PDF/TXT 显示为下载条目。草稿附件仅操作员可见，随内容发布或撤回控制公开访问。
- **列表简介**：选填，仅用于列表和首页卡片。留空时从正文自动摘取最多 160 个字符，不改写已保存的正文或摘要。正文页不再重复展示简介。
- **预览**：与前台共用文章展示组件，封面、正文图和图片附件均可在“保存并预览”中确认。

前台保留顶部主导航；栏目页提供当前栏目的子分类筛选，文章页使用面包屑和“返回列表”，不再重复显示左侧全站栏目导航。

## 栏目与站点

- 栏目设置可增加、改名、排序、停用栏目，选择已有内容类型和展示模板。
- 建议最多两级。已有内容的栏目不能直接改变内容类型。
- 被子栏目、内容或历史版本引用的栏目不能删除，通常使用停用。
- 站点配置可维护品牌文字、轮播、快捷入口、建设单位、额外业务链接与页脚。
- 首页轮播：每一张可分别配置标题、说明、顶部标签、按钮文字、跳转地址和图片；建议上传 1920×600 横幅。保存后图文一起切换。标签留空可隐藏，跳转地址留空不显示按钮，未上传图片时轮流使用两种默认插画。
- 建设单位图片：默认使用用户提供图4中的七家单位标识。进入“内容管理 → 站点配置 → 建设单位”，点击“添加”，填写单位名称与可选官网地址，上传 PNG/JPG（单张不超过 10 MB），最后点击“保存站点配置”。自定义列表会替换默认标识；上传后可预览、更换或移除图片，按原比例完整展示，全部单位自动换行、居中排列。使用“↑”调整顺序。
- 首页底部只显示建设单位，不再显示上级部门。
- 备案信息：在“站点配置”顶部填写实际备案号和可选备案查询链接后保存。未填写号码时不展示备案项；所有门户页面统一显示提供的中心标识、累计访问量及“版权所有：新材料大数据中心”。
- 主导航将“数据资源”“数据产品”依次排列在“新闻中心”之后，其余栏目的相对顺序保持不变。
- 首页不展示“数据检索”“在线开发”“在线研发”“全球材料数据库”入口，数据资源直接进入目录，不展开下拉菜单。首页快捷入口最多展示两个。
- 对默认栏目修改路径标识后，检查并同步修改站点配置中手工填写的链接。
- 普通人员只浏览内容和管理自己的账号，不显示发布入口；后端仍实施授权校验。

## 正式部署

提供 `deploy/compose.yml` 与前后端 Dockerfile。当前工作环境没有 Docker/MySQL 服务，因此该模板未在真实容器和 MySQL 环境运行验收。

1. 准备正式域名、HTTPS 反向代理和 Docker 环境。
2. 复制 `deploy/.env.example` 为 `deploy/.env`，设置全部密码与 APP_ORIGIN。
3. 正式环境必须关闭演示数据，设置 APP_PRODUCTION=true、SECURE_COOKIE=true，并使用 MySQL。
4. 在项目根目录执行 `bash ./start.sh`，或在 `deploy` 目录执行 `docker compose up -d --build`。服务器需提前安装并启动 Docker Engine 和 Docker Compose 插件。
5. 将 HTTPS 反向代理指向宿主机 `127.0.0.1:8090`。8090 是内部 HTTP 入口，不直接向公网开放。
6. 外部访问地址必须与 APP_ORIGIN 精确一致；HTTPS 必须真实可用，否则 Secure Cookie 无法正常工作。
7. 数据库不映射宿主机端口，后端仅通过内部网络供 web 服务访问。
8. 完成账号、上传、发布撤回、数据库迁移和中心认证的目标环境验收后再投入正式使用。

应用初始化只在指定用户名不存在时创建操作员，不会覆盖现有账号密码。初始化成功后移除运行环境中的引导密码；Compose 中相关变量可改为普通受控环境注入。角色变更应由数据库运维事务执行并写 audit_logs，不开放普通用户可调用的角色修改接口。

## 备份与恢复

- 本地 H2：先停止服务，再一起备份 backend/data 和 backend/uploads。
- 生产 MySQL：使用数据库一致性备份，与上传文件卷同时备份；保存应用配置和令牌加密密钥至独立受控位置。
- 恢复时先恢复数据库和文件、部署匹配版本，再启动并检查迁移结果。不要只恢复数据库而遗漏附件文件。
- 已执行的 Flyway 脚本不直接修改；新增脚本使用递增版本号。
- 回退代码前核实数据库兼容性。破坏性升级应通过备份恢复，不提供盲目的自动降级脚本。

## 日志与故障

- 本地脚本日志在 `.runtime/backend.log` 和 `.runtime/frontend.log`，异常日志对应 `*-error.log`。
- 端口冲突：先确认是不是本项目已启动，再使用 Stop-Local.ps1；不要终止不明进程。
- 登录提示来源不匹配：使用 APP_ORIGIN 配置的同一地址访问。
- 认证未配置：本地注册登录正常；按照中心接入文档补全后端配置。
- 图片或附件 404：检查是否有仍公开的内容引用该文件；草稿附件不允许匿名访问。
- 内容更新冲突：重新打开内容，合并其他操作员已保存的修改后再提交。
